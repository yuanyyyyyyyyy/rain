## 一、审计结论（现状）

- 上传表单仅 3 控件：file（multiple）+ 分组下拉（STREET/LIGHT/DAILY 写死）+ date（`PhotosPage.vue:8-17`）；**整批共用同一个分组和同一个日期**（`PhotosPage.vue:143-151`）。
- 后端 `PhotoService.upload()`（PhotoService.java:44-98）：宽高是自动提取的（ImageIO），**拍摄日期零自动化**——全仓 grep `exif|metadata-extractor` 代码零命中，pom 里只有 thumbnailator。
- `Photo` 实体（Photo.java:12-47）：pid/origName/shotDate/width/height/groupName/sortNo/isHero/createdAt，**无 caption/描述/相机参数字段**。
- 存储规则：原始副本 → `admin/server/var/photos-orig/`（gitignore）；压缩产物（长边 1600/q80）→ `G:/Improve/MI/rain/public/photos/pXX.jpg`。
- 佐证 EXIF 可用：`docs/素材/照片清单-photos-manifest-20261108.json` 的 30 条日期就是当初人工读原图 EXIF 整理的（审计报告 P1-2 记录曾据 EXIF 修正 p20/p22）——**数据存在，只是没把能力做进代码**。
- 其他体验问题：批量顺序 await 一张失败中断整批无明细（:142-156）；排序=全组 N 个并发 PUT（:192-196）；跨组拖拽被禁（:187）；无拖拽/粘贴上传；「photos.js 片段手工粘贴」是 M2 过渡残留（:30-34）；EXIF Orientation 未处理，竖拍宽高可能颠倒（PhotoService.java:69-77）。

## 二、任务清单

### P0-1 后端 EXIF 自动提取拍摄日期
- 依赖：`com.drewnoakes:metadata-extractor:2.19.x`（纯 Java、零传递依赖、Apache 2.0，JPEG/PNG/HEIF 均可读）加进 `admin/server/pom.xml`。
- 插入点现成：`PhotoService.upload()` 里原始副本已先落盘（:63-66），对 `origTarget` 提取：
  - SubIFD `DateTimeOriginal`（拍摄时间）+ `OffsetTimeOriginal`（时区）；时区缺失按 `Asia/Shanghai` 落 LocalDate。
  - IFD0 `Orientation`：竖拍（6/8）时**交换宽高**再入库（或按 orientation 旋转输出，最小实现 = 修正宽高即可）。
  - EXIF 缺失回退：`Files.getLastModifiedTime`（文件修改时间），并在响应里标注来源（exif/mtime/manual）让 UI 显示"已自动识别"。
- 上传 API 响应回传解析出的日期，前端自动填入（仍可手改）。

### P1-1 前端预提取（体验更优，与 P0-1 互为兜底）
- `admin/ui` 引入 `exifr`（npm，纯前端）：选中文件后立即在预览条显示提取到的日期/方向，可改；后端提取作兜底。
- 上传区改为「选片 → 预览列表（缩略图 + 自动日期 + 分组可逐张改） → 确认上传」两段式。

### P1-2 批量上传体验
- 逐张指定分组/日期（默认沿用整批值）；失败逐张明细 + 单张重试（替换 :142-156 的顺序 await）；并发限制 2-3 防止 20MB×N 打爆内存。
- 支持拖拽/粘贴到上传区（`drop`/`paste` 事件，无新依赖）。

### P1-3 数据模型扩展（为前台 caption 铺路）
- `Photo` 加 `caption`（可空）列；PhotoDataGenerator 生成 photos.js 时带出（前台 `PhotographyPage`/Lightbox 图注从 `PLATE.xxx — 日期` 扩展为可显示 caption，需同步改前台消费端，注意这会动 `src/data/photos.js` 结构——发布产物，通过生成器改）。
- 可选列：`camera`（EXIF Make/Model），前台 caption 扩展用。

### P2 清理
- 删除「photos.js 片段手工粘贴」残留 UI（PhotosPage.vue:30-34、PhotoService.java:100-105 对应逻辑）。
- 排序保存从"全组 N 个并发 PUT"改为一个批量端点 `PUT /api/photos/reorder`（PhotoController 加方法）。
- 跨组拖拽放开（onDrop :187 移除 groupKey 校验，换组时更新 groupName）。
