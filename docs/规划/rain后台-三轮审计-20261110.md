## 二、本轮新发现与分级（均为前两轮审计未覆盖）

| # | 发现 | 级别 | 说明 |
|---|---|---|---|
| 1 | **登录限流可被 XFF 头伪造绕过** | **P1 安全** | `AuthController.clientIp` 无条件信任 `X-Forwarded-For` 首段（攻击者可控）。后端仅绑本机时实际风险低，但限流（登录 5 次/15 分、留言 60s/IP、埋点 30 次/分）全部可被轮换 XFF 绕过——二轮只修了内存增长，没修信任语义本身。二轮记录中「XFF 可伪造轮换」只作为内存问题被提及。 |
| 2 | **服务监听全部网卡** | P1 安全 | `server.address` 未配置 → 0.0.0.0，局域网可达管理 API。当前用法纯本机，应默认回环绑定。 |
| 3 | **登录存在用户名枚举时序差** | P2 安全 | 用户不存在时跳过 BCrypt matches（约 50-100ms 可测差）。 |
| 4 | **项目卡片排序无管理入口** | **P1 功能** | `project_detail.sort_no` 存在且生成器按它排序（总纲 P2 只修了一半：从"插入顺序"改为"sortNo 顺序"），但无 API 无 UI 修改 sortNo → 新项目永远排最后，顺序不可调。 |
| 5 | **头图照片可以直接删除** | P2 | `setHidden` 有头图防护，`deleteRecord` 没有 → 删头图后发布必然失败（有明确报错可恢复，但防护成本 3 行，应与隐藏行为一致）。 |
| 6 | **删除照片永久销毁原始副本** | **P2 资产** | `deleteFiles` 连 `var/photos-orig/` 原图一起删。原图是用户资产且不入 git（var/ 已忽略），误删即永久丢失。压缩产物/缩略图可再生成，原图不可。 |
| 7 | `GET /api/content/screenshots/{slug}` 未校验 slug | P2 | `frontendPublicDir.resolve("screenshots").resolve(slug)`，`create()` 有 slug 正则而这里没有（Tomcat 默认拒 %2F，实际穿透难，防御纵深应补上）。 |
| 8 | 留言列表返回 `ipHash` | P3 | 管理台 UI 未使用该字段，无必要出网（虽然已是哈希）。 |
| 9 | 改密后旧 JWT 仍有效至过期（120 分钟） | P3 | 无吊销机制。单管理员可接受的折衷：前端改密成功立即清 token 强制重登，README 注明旧 token 窗口。 |
| 10 | `deployStatus` 每次调用新建 HttpClient | P3 | 连接池不复用，提为字段即可。 |

**前两轮已明确跳过、本轮不再提**：Worker CORS `*`（收益≈0）、`/messages` 分页（等真实需求）、字体 500 档砍除（会改渲染）。

**评估后不做的（本轮）**：
- JWT 加 tokenVersion 吊销：每请求查库 + 改动面大，单管理员本机收益低，采纳 #9 的前端折衷。
- Spring Boot 3.3.5 升 patch 版：3.3.x 系列内无已知高危（安全修复集中在 3.4/3.5 线的 Framework 6.2），且本机 Maven 源可用性未验证，避免为升级引入不可验证变更；建议下次开发窗口一并升 3.4.x。
- 照片软删回收站（对齐留言）：`hidden` 开关已挡展示风险；原图入回收档（#6 处置）已覆盖数据丢失风险，全量软删留待真实需求。
