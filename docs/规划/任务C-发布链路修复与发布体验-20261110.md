# 任务 C：发布链路修复 + 发布体验（2026-11-10）

> 对应总纲：`rain-并行开发总纲-审计与任务分解-20261110.md`。用户问题 4：「我在后端移动了照片，为什么网站没有实时改变，是需要发布才行吗」。
> 建议分支：`feat/task-c-publish-fix`。**第二批执行（建议在 B 之后，共享 PhotosPage.vue）**。

## 一、审计结论

- 「移动后不实时」是**发布制架构，设计如此**：拖拽排序 → `PUT /api/photos/{id}` 只改 MySQL（PhotoService.java:110-121）；前台 `PhotographyPage.vue:73` 读的是打包进 bundle 的 `src/data/photos.js`，该文件只在发布时重写（PublishService.java:69）；公网生效 = push → GitHub Actions 构建 → Pages，**合计约 1.5–3 分钟**。手册 :119 FAQ 已明示。
- 真正的缺陷是**体验层**：改完没有任何「有未发布变更」提示；发布后只说"约 1 分钟更新"，不查 Actions 实际状态。
- **P0 真 bug（用户尚未感知）**：`PublishService.commitAndSync()` 只 `git add src/data`（PublishService.java:159），**新上传的 `public/photos/pXX.jpg` 永远不进发布 commit** → 发布后公网照片 404。历史佐证：commit d0fdcd3 "restore p01.jpg ... after M2.1 test-upload overwrote it" 正是此断链的事故善后；`git log -- public/photos` 仅 2 个提交。**当前上传→公网展示这条路是断的**。
- commit 43a02c7 涉及的 sync-via-api patch（latest-match + auto deploy trigger）**已完整入库**，无半成品残留（`git show 43a02c7` 核实）；`tools/sync-via-api.py:55-58` latest-match、:92-95 `gh workflow run deploy.yml` 补触发。
- 发布链路现状：`POST /api/publish` → PhotoDataGenerator/SiteDataGenerator 生成 → tmp 原子写回（:88-116）→ `npm run build`（:197-222）→ commit+push（失败回退 sync-via-api.py，:156-181）→ publish_log 落库。

## 二、任务清单

### P0-1 发布 commit 带上照片二进制（修断链）
- `PublishService.java:159`：`git add src/data` → `git add -A src/data public/photos`（`-A` 同时覆盖照片删除场景）。
- `tools/sync-via-api.py` 重放本地 commit 天然带上 jpg，无需改（核实其 blob 上传含二进制路径）。
- 验收：上传一张新照片 → 发布 → commit 里含 `public/photos/pXX.jpg` → 公网 `https://yuanyyyyyyyyy.github.io/rain/photos/pXX.jpg` 200。

### P1-1 「未发布变更」角标（解决"保存了≠生效了"的感知问题）
- 后端提供脏检测：新增 `GET /api/publish/dirty`，比较 `photo.updated_at` / `project_detail.updated_at`（若实体无 updated_at 列则加 `@UpdateTimestamp`）与 `publish_log` 最新成功时间的 max。
- 前端：PhotosPage / ContentPage / LayoutPage 侧栏显示角标（如侧栏「04 发布」项上加红点 + N）；发布成功后清除。
- **回答用户原话**：是的需要发布，但 UI 要主动告诉你"你有改动没发布"。

### P1-2 发布进度真实反馈
- `PublishPage.vue:26-30` 的"约 1 分钟更新"改为真实状态：Spring 加 `GET /api/publish/deploy-status` 代理 GitHub Actions API（`repos/yuanyyyyyyyyy/rain/actions/runs?branch=main`，公开仓库匿名可读；**由后端代理**——国内直连 api.github.com 不稳），轮询展示 `排队中 → 构建中 → 已部署（耗时）`。
- publish_log 记录最终部署结果（可选：commitAndSync 后由后端轮询一次写入）。

### P2 可选
- 「保存并发布」合并按钮（PhotosPage/ContentPage 保存后直接触发 publish，减少两步心智）。
- 自动发布防抖：若做全自动（排序后 N 秒自动发布），需对拖拽做防抖 + deploy.yml cancel-in-progress 已有保护；**不建议默认开启**，保留手动发布为主。

## 四、验收标准
1. 新上传照片 → 发布 → 公网可访问（P0 断链修复的核心验收）。
2. 改动照片顺序后，侧栏出现未发布角标；发布后角标消失、进度显示真实 Actions 状态直至"已部署"。
3. push 被墙场景：sync-via-api.py 回退通道仍工作（可用 `git remote set-url` 模拟或读 publish_log 历史验证）。
