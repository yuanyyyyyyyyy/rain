## 三、事故与处置：GitHub Pages deploy job 无法创建

**现象**：18:08 起连续 6 个 deploy run 失败——build job 正常，deploy job 从未被创建，GitHub 提示 "likely failed because of a workflow file issue"（但文件未变、树完整、Pages 配置正常、手动创建 deployment 成功）。

**定位过程**：对照实验（verify workflow 正常 → Actions 整体健康）→ 逐项排除（workflow 文件、Pages 配置、deployment 服务）→ 移除 deploy job 的 `environment: github-pages` 块后部署立即恢复。

**结论与处置**：GitHub 侧 github-pages environment 的调度异常。environment 块已临时移除（仅损失 run 页面的部署 URL 展示，部署功能完全正常）；**GitHub 侧恢复后可撤销 commit 0309265 恢复 environment 块**。附带处置了 sync-via-api 重放通道的既有问题（此前的 startup failure 与重放双触发叠加加重了排查噪声）。

## 四、评估后跳过项（含理由）

- Worker CORS 收紧（`*` → 回显 Origin）：请求带 Bearer token 前提下 `*` 无实际泄露面；管理台 origin 是动态本地端口，硬编码脆弱。收益 ≈0。
- /messages 分页：LIMIT 100 对个人站留言量绰绰有余，等真实需求出现再做。
- 字体 500 档砍除：h2/.cn 实际使用且 --font-sans 是 Manrope+Noto 组合栈，砍掉会改变渲染。
