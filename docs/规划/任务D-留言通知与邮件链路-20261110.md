# 任务 D：留言通知与邮件链路（2026-11-10）

> 对应总纲：`rain-并行开发总纲-审计与任务分解-20261110.md`。用户问题 3：「怎么我在网站模拟发了邮件，我的邮件看不到、收件箱看不到，后端数据库表数据也没变化」。
> 建议分支：`feat/task-d-notify`。**第一批执行（与 B、E 真并行，文件零交集）**。

## 一、审计结论（为什么"看不到"——四层原因）

1. **最根本：整个系统没有"发邮件"能力**。全仓无 SMTP/邮件 API 代码（pom 无 mail starter；worker.js 只入库；wrangler.toml 仅 D1 绑定）。系统设计从来就是"收留言入库"，不投递邮件。
2. 管理台里唯一与"发邮件"沾边的是收件箱里访客邮箱的 mailto 链接（`InboxPage.vue:25`）——点它只是唤起本机邮件客户端写一封发给访客的邮件，系统不参与不存库。没有"发送/模拟发邮件"按钮。
3. 留言只进 Cloudflare D1（`worker.js:75-90` → D1 `messages` 表，schema.sql:14-24），前台表单固定 POST Worker（`ContactSection.vue:81`、apiBase 硬编码 `site.js:8`）；本地 MySQL `message` 表已"断供"（公网表单不经过 Spring）。**两套存储完全隔离，无同步机制**。
4. 收件箱看不到：管理台未配「数据源」时 InboxPage 读本地 MySQL → 空表（`InboxPage.vue:68-81`）。配置值见任务 E / `cloudflare/.admin-token.local`。
   另：国内直连 workers.dev 间歇受限时，表单失败走降级文案（ContactSection.vue:86-90），此时**三处（D1/MySQL/邮箱）都没有**。

## 二、任务清单

### P0-1 Worker 收到留言后转发站长邮箱（真正的"邮件通知"）
- 位置：`worker.js` 表单入库成功处（:88 之后），`context.waitUntil` 异步发送，**发送失败不影响入库与 200 响应**（try/catch 吞错 + console.error）。
- 服务选型（站点暂无自有域名）：
  - **推荐 Brevo**（免费 300 封/天，发件人验证后可发任意收件人，163 可达）：`POST https://api.brevo.com/v3/smtp/email`，header `api-key`。
  - 备选 Resend（免费 100 封/天）：未验证自有域名时**只能发给 Resend 注册账号本人**，要发 163 需先绑域名。
  - 不用 MailChannels（2024 年已停 Workers 免费集成）；Cloudflare 原生 `send_email` binding 需自有域名 + Email Routing。
- 密钥：`npx wrangler secret put BREVO_API_KEY`（或 RESEND_API_KEY），**绝不写进代码/仓库**；收件地址读 `env.OWNER_EMAIL`（secret 或 vars，值 = site.js:16 的站长邮箱）。
- 内容：访客姓名/邮箱/留言摘要 + 时间，reply-to 设访客邮箱（可直接回复）。
- 部署与验证：`npx wrangler deploy`；跑 `.github/workflows/verify-collector.yml` 的 E2E（或本地 curl 一条测试留言）确认 D1 入库 + 邮箱收到。
- 防滥用：留言已有限频（同 IP 60s），邮件侧再加每日上限（如 D1 计数或简单 env 开关）防刷爆配额。

### P1-1 收件箱空态自解释
- `InboxPage.vue:58` 空态文案补一句：「公网访客留言存储在 Cloudflare D1；需在 侧栏-数据源（或 06 设置）配置 Worker 地址与 ADMIN_TOKEN 才能查看」。配置入口在任务 E 中会搬进设置页，两任务注意文案口径一致。

### P2 一致性小修
- `ContactSection.vue:86-90` 与 `site.js:7` 注释不一致：要么失败时真的弹 mailto（`location.href = mailto:`），要么改注释为"失败提示邮箱地址"。二选一，别让下一个审计再误判。
- 顺带（若任务 E 未做）：侧栏未读徽标恒读本地（LayoutPage.vue:38-45）——**归任务 E**（与数据源状态一起改），D 不动 LayoutPage。

## 四、验收标准
1. 前台提交一条留言：D1 入库 + 站长邮箱在 1 分钟内收到通知邮件，回复直接送达访客邮箱。
2. 邮件 API 故障（填错 key）时：留言仍入库、前台仍收到"已收到"，仅 Worker 日志报错。
3. verify-collector E2E 通过；不产生任何凭据入库。

## 五、冲突与依赖
- `worker.js` 本任务独占；`site.js` 只动第 7 行注释（锚点区外，安全）。
- 与任务 E 无文件交集（E 动 SettingsPage/LayoutPage/DashboardPage/api.js）。
- 需要用户配合：注册 Brevo/Resend 账号、`wrangler secret put`、（可选）后续买域名绑 Worker 以获得更好发信信誉。
