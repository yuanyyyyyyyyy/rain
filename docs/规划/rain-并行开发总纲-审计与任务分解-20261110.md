### 协作模式建议

- **每个会话单独开分支**（`feat/task-b-photo-exif` 等），完成后逐个 merge 回 main，避免多会话同工作区互相踩。
- **并行期间不要有两个会话同时点「04 发布」**：发布 = git commit + push + Pages 部署，连发会触发 deploy.yml 的 `cancel-in-progress` 取消旧部署。
- 内容数据文件 `src/data/*.js` 是发布产物（锚点区内），**任何任务都不要手改**；内容一律走管理台 → DB → 发布。
- 凭据（ADMIN_TOKEN、邮件 API key）只进 `wrangler secret` / 本地留档文件，不入库。

## 四、forge 简历内容存档（来自用户提供的截图，任务 A 直接使用）

**Forge — 面向多轮复杂任务的 Agent Harness** ｜ 独立设计开发 ｜ 2026.01–2026.05

- 项目描述：面向多入口 AI Agent 场景的统一 Runtime：CLI、终端 TUI、后台 Gateway、定时任务与飞书/QQ/企业微信等消息渠道共享同一执行链路，Runtime 统一负责调度、上下文组装、工具执行与会话持久化，消除各入口重复实现。
- 技术栈：Python、TypeScript、asyncio、LiteLLM、MCP、pytest、uv
- 统一执行模型：抽象 Turn 执行单元，CLI/TUI/Gateway/消息渠道共享同一 Runtime，统一编排 Agent 循环、会话隔离与后台任务并发。
- 任务调度：asyncio 实现会话级串行 + 跨会话并行调度；4,160 次真实请求 0 丢失 0 重复，端到端 P95 13.57s→11.66s，验收通过率 99.95%。
- 上下文与成本优化：上下文拆分系统/工具/滚动历史三层，前缀稳定利用 Provider 缓存，对照实验（72 Trials）成本降低约 72%、缓存命中率约 74%。
- 工具并发：按读写属性分级并发，只并行安全读取；8 路微基准中位耗时由串行 374ms 降至 113ms，结果与顺序执行一致。
- 可观测与可复现：自建 ForgeBench 评测体系：冻结模型/参数/Prompt 变量、保留执行凭证与证据摘要，防止模型波动误判为优化收益。
