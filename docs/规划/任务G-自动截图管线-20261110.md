# 任务 G：自动截图管线（2026-11-10）

> 对应总纲：`rain-并行开发总纲-审计与任务分解-20261110.md`。用户问题 2：「网站需要的相对应的项目截图（有几个项目就弄几个）能自己自动截图加进去吗」。
> 建议分支：`feat/task-g-screenshots`。**第三批执行（依赖任务 A 完成）**。

## 一、审计结论

- **现状零基础**：根目录与 admin/ui 均无 playwright/puppeteer；无截图相关 CI job；两份规划文档只把截图列为"待素材"，从未评估自动化。
- **截图消费链路已就绪**：图片放 `public/screenshots/<slug>/` → 管理台 shots 表单 datalist 自动列出该目录（ContentPage.vue:241 ← `GET /api/content/screenshots/{slug}` ← ContentService.java:150-159）→ 保存 items → 发布导出 → 前台按 `BASE + src` 渲染网格 + Lightbox（ProjectDetailPage.vue:44-46、117-128）。`pending:true + wanted[]` 是占位机制。
- 三个项目的截图需求文档已存在（`docs/素材/截图需求-{云枢,IntelNexus,Shimmer}-20261109.md`）：云枢 5 张（**脱敏红线**）、IntelNexus 6 张（Streamlit）、Shimmer 3+3 张；规格统一宽 ≥1440px、单张 ≤2MB、命名 `<slug>-NN.png`。
- **范围分级（关键判断）**：
  - **rain 本站：100% 可全自动**（自己就能起 dev server 截自己）；
  - IntelNexus（Streamlit localhost）、Shimmer（Vite+Express）：本地能起服务即可自动；
  - 云枢：依赖 MySQL/Redis/Nacos + 演示数据 + **脱敏人工审** → 半自动（脚本截 + 人审）；
  - **forge：纯 CLI/库形态无 Web UI，浏览器截图无对象** → 不设 shots 节，用 impl/metrics/（可选 SVG arch）表达。

## 二、任务清单

### P1-1 本地 Playwright 截图脚本（推荐方案）
- 依赖：`npm i -D playwright` + `npx playwright install chromium`（仅 devDependencies）。
- 新增 `tools/screenshots.mjs`：
  - 自起服务：`npm run build && vite preview`（产物截图比 dev 准，无 HMR 水印）；或复用已起的 dev server（`--url` 参数注入）。
  - 配置表驱动：`[{ slug:'rain', base:'/', shots:[{path:'/', name:'rain-01'},{path:'/projects/yunshu',name:'yunshu-01'},…]}]`——**rain 的截图就是站内各页**（首页 Hero/Works/摄影页/详情页），一石二鸟：既是 rain 项目自己的 shots，也顺带产出 yunshu/intelnexus/shimmer 详情页骨架图（但真项目截图仍以各项目本地服务为准）。
  - viewport 1440×900 起，`fullPage: true`；输出 `public/screenshots/<slug>/<slug>-NN.png`；超 2MB 时降为 JPEG q85 或用 sharp 压缩（可选）。
  - 输出清单打印 + 与 `docs/素材/截图需求-*.md` 的 wanted 对照提示缺哪张。
- `package.json` 加 `"shots": "node tools/screenshots.mjs"`；内容改版后手动跑一次（频率低，不做 CI 定时）。

### P1-2 接入仍走管理台（保持"DB 是唯一内容源"纪律）
- 脚本只产出图片文件；图片进详情页 = 管理台 shots 表单选文件 + 写图注 + 取消 pending → 发布。**不要手改 `src/data/projects/*.js`**。
- 前置：任务 A 的 P0-2（caption/fig 字段修复）必须已合入，否则图注 undefined。

### P2 可选
- CI job（ubuntu + playwright + preview + commit 截图）：与"管理台发布 → 本地 commit+push"形成双向写库，复杂度高、页面改版频率低多数空跑 → **不推荐首选**。
- IntelNexus/Shimmer 的自动截图子命令（`--target intelnexus` 需其本地服务地址），做成参数化扩展点即可，不强求本期实现。
- 云枢：脚本只截"演示数据/打码后"的页面，产出后必须人工过一遍脱敏再接入。

## 三、涉及文件
- `tools/screenshots.mjs`（新增）、`tools/README.md`（补说明）、根 `package.json`（script + devDependency）
- `public/screenshots/<slug>/*.png`（产物）
- `docs/素材/截图需求-*.md`（完成后回填状态）
- 不动任何 Java / 管理台代码

## 四、验收标准
1. `npm run shots` 一键产出 rain 全站截图到 `public/screenshots/rain/`，规格达标（≥1440 宽、≤2MB）。
2. rain 详情页 shots 节取消 pending、选图、发布后，公网详情页截图网格 + Lightbox 正常（图注正常显示——依赖 A 的字段修复）。
3. 脚本对"服务未起/页面 404"有清晰报错，不留半截产物。

## 五、冲突与依赖
- **硬依赖任务 A**（rain 详情页注册 + caption 修复 + rain shots 节存在）。
- 与 B/C/D/E/F 无文件交集（tools/ 与根 package.json 独占；根 package.json 与 B 的 admin/ui/package.json 是两个文件，不冲突）。
- 产物 png 入库会让仓库变大：单张 ≤2MB × 约 15 张可接受；若后续增多再考虑 release asset/LFS。
