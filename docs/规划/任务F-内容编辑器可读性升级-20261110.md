## 一、审计结论（"简陋/看不懂"的真实成因）

编辑器**已是按类型分节的结构化表单**（ContentPage.vue，607 行），不是 JSON 编辑器。看不懂的直接原因：

1. **「新增节」下拉是英文技术枚举**：`shots / impl / metrics / pits / text`（ContentPage.vue:150-156、:166 EDITABLE_TYPES，与 ContentService.java:29 一致），没有任何中文解释——用户无从知道 impl=核心实现三段式、pits=踩坑复盘。
2. **kicker 编号约定不可见**：标题输入框自动拼 `NN / ` 前缀（:58-62），`01 / OVERVIEW` 由页面渲染不存库、编号从 02 起算（padNo = i+2，:245）——这个约定只写在后端注释里（ContentService.java:22），界面零说明。
3. **无任何实时预览**：前台效果（Kicker 编号、三段式布局、数据卡）全靠想象。
4. 字段名英文裸奔：headline/summary/headerNote/kicker/wanted/note/labels，仅少量中文 placeholder。
5. 保存≠生效的两步心智（保存落库 → 04 发布）只在保存成功 msg 里提了一句（:291）。
6. 新建项目用 **3 连原生 prompt()**（:197-201）依次问 slug/名称/简介。
7. text 节换行丢失：前台 `.gains` 无 `white-space: pre-line`（ProjectDetailPage.vue:382-388），textarea 敲的换行挤成一段。
8. 死代码：:575-606 的 `.modal` 样式是已删 export 面板遗留（bd6d23c）。
9. 后端 PUT 为全量替换（ContentController.java:39-46），先校验后落库，`validateAndRenumber()`（ContentService.java:162-226）逐类型限定字段并重排 kicker——**校验器是完善的，升级 UI 不用动后端契约**。

## 二、任务清单

### P1-1 「新增节」中文化 + 引导
- 下拉选项改中文带说明：`界面截图（shots）— 上传截图或先列 wanted 占位`、`核心实现（impl）— 问题/方案/效果三段式条目`、`数据指标（metrics）— 数值+变化，前 3 条进首页卡片`、`踩坑复盘（pits）— 坑 + 经过与解决`、`正文段落（text）— 纯文本段落`。
- 旁挂固定说明：「01 概述由页面自动生成；新增节编号自动顺延（02 起），无需手填」。
- 分节卡片头部显示当前类型中文名 + 折叠/展开（长页面可读性）。

- 标题输入框只收纯标题（去掉 `NN / ` 拼接外露，:58-62）；后端保存时本就会重排（ContentService.java:224），前端展示时剥离前缀显示即可。存量数据的 `NN / ` 前缀在编辑时自动剥掉。

### P1-3 实时预览

- 进一步（可选）：text/impl 的 textarea 旁即时渲染（markdown-it 或纯换行渲染）。
