# 截图需求 · Forge（Agent Harness）

> 交给 forge 项目的 agent。截图用于作品集网站 `/projects/forge` 详情页「界面实录」板块（该节当前为 pending 占位，回收后切成实图）。
> 回收后处理：存入 `public/screenshots/forge/`，把 forge 详情数据的 shots 节从 `pending: true` 替换为 items 数组（图注网站侧已备好）。

## 特别说明：Forge 没有网页界面

Forge 是 CLI / 终端 TUI / 后台 Gateway / 消息渠道形态的 Agent Runtime，**没有浏览器页面**——所以截图形态是**终端截图、聊天记录截图、评测输出**，这恰恰是这个项目的真实感所在，不需要伪装成 Web 界面。终端截图在本站有先例可看：真实感比美化重要。

## 隐私与脱敏

- **终端截图**：本机用户名、绝对路径、API Key / token（LiteLLM 环境变量、provider key）必须打码；建议直接在终端里 `export PROMPT=...` 之类的假路径跑演示，或事后涂抹
- **聊天渠道截图（F5）**：群名、其他群成员的昵称/头像必须处理（那是别人的隐私），只保留 bot 的对话区域，或用只有自己的测试群
- **ForgeBench 报告（F6）**：模型供应商账号、费用金额如不愿展示可打码
- 演示任务的会话内容避免真实敏感工作内容

## 需要的截图（6 张）

| # | 画面对应 | 截什么 | 对应文案要点 |
|---|---|---|---|
| F1 | 统一执行模型 · TUI 主界面 | TUI 会话面板：单会话完整执行一轮 Agent 循环（可见工具调用步骤、流式输出） | 五类入口共享同一 Runtime、Turn 执行单元 |
| F2 | 任务调度 · 并发视图 | **多会话同时进行**的画面：TUI 多面板 / Gateway 会话列表 / 日志交错输出，能看出"会话内串行、跨会话并行" | 4,160 次真实请求 0 丢失 0 重复 |
| F3 | 工具并发 · 调用过程 | CLI 或日志里一次多工具调用的过程输出：多个读取类工具并行执行、耗时统计（若有 374ms→113ms 类基准输出更好） | 按读写属性分级并发 |
| F4 | 上下文与成本 · 统计面板 | LiteLLM spend / 缓存命中统计、或自建的上下文组装日志（系统/工具/滚动历史三层拆分可见） | 成本 -72% · 缓存命中 ≈74% |
| F5 | 消息渠道 · 真实对话 | 飞书/QQ/企业微信里给 bot 派一个任务并收到完成的回复（对话区域即可）——**最能体现"多入口共享执行链路"的画面** | 消息渠道与 CLI 共享同一执行链路 |
| F6 | 可观测 · ForgeBench 评测 | 评测运行控制台或报告：冻结变量说明、Trials 进度、通过率/耗时汇总（72 Trials 对照实验的产出） | ForgeBench：收益可归因、可复现 |

优先级：F1、F5、F2 三张最能立住"统一 Runtime"的叙事；F3/F4/F6 是加分项。不足 6 张可先交 3 张，网站侧 pending 节会显示未收齐的 wanted 清单。

## 规格要求

- **终端截图**：窗口宽度 ≥1200px（或按 16:9 全屏）；建议裁掉终端标题栏/标签栏，只留内容区；字号放大到录屏可读的程度；同一批截图用同一套配色主题（别深浅混用）
- **聊天截图**：宽 ≥1000px，只截对话区域，不要带整屏聊天列表
- 文件名 `forge-01.png` ~ `forge-06.png`（对应 F1-F6）
- 单张 ≤2MB（终端截图超出可适当降分辨率，文字仍需可读）
- 格式 PNG（文字锐度优先）

## 网站侧用途说明

- 展示位置：详情页「界面实录」两列网格 + Lightbox，与架构图（01 分节）、核心实现（三段式）互补
- 图注文案网站侧负责（已拟好草稿）；截图里若有值得点出的细节（比如 TUI 里某个并发会话的状态列），附一句话说明即可，网站侧会写进图注
- 与云枢/IntelNexus 不同：forge 的界面就是终端与聊天——评审者看到真实终端反而加分，不要试图美化成 Web 风格
